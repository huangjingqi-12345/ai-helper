# Px-Lite 状态机定义

> **版本:** 1.0 · **日期:** 2026-05-14
>
> 每个带有 `status` 字段的实体都有正式的状态机。本文档定义所有合法状态、转换、触发条件和守卫。

---

## 1. 内容生命周期（`ContentItem.status`）

```
                    ┌──────────┐
        ┌──────────►│ rejected │◄─────────────────┐
        │           │ (已驳回)  │                   │
        │           └──────────┘                   │
        │ (任意审批节点驳回)                          │
        │                                          │
   ┌────┴───┐     ┌───────────┐    ┌──────────┐   │
   │  draft │────►│ reviewing │───►│ reviewed │   │
   │ (草稿)  │     │  (审核中)  │    │ (审核通过) │   │
   └────────┘     └───────────┘    └────┬─────┘   │
     ▲  │          ▲                     │         │
     │  │          │ (修改后                │         │
     │  │          │  重新提交)             ▼         │
     │  │          │              ┌───────────┐    │
     │  │          └──────────────│ published │    │
     │  │                         │  (已上线)  │    │
     │  │                         └─────┬─────┘    │
     │  │                               │         │
     │  │                               ▼         │
     │  │                         ┌─────────┐     │
     │  │                         │ offline │─────┘
     │  │                         │ (已下线)  │
     │  │                         └─────────┘
     │  │                               │
     │  └───────────────────────────────┘
     │         (重新发布已下线内容)
     │
   [AIGC 生成 / 医生提交]
```

### 转换表

| 从 | 到 | 触发 | 谁 | 守卫 / 副作用 |
|----|----|------|-----|-------------|
| *(新建)* | `draft` | AIGC 生成完成 或 医生从 DX 提交 | 系统 / 医生 | 创建 ContentItem 记录 |
| `draft` | `reviewing` | 作者提交审核 | 医生 / 运营 | 创建 ApprovalTask，设置 currentIdx=0 |
| `reviewing` | `reviewed` | 最终审批节点通过 | 审批系统 | 流程中所有节点已通过 |
| `reviewing` | `rejected` | 任意节点驳回 | 审核人 | 设置 ApprovalTask.rejected=true；记录驳回原因 |
| `reviewed` | `published` | 运营点击"一键上线" | ops-admin / ops-reviewer | 设置 publishedAt = now |
| `published` | `offline` | 运营点击"一键下线" | ops-admin | 记录操作人和时间 |
| `offline` | `published` | 运营重新发布 | ops-admin | 更新 publishedAt |
| `rejected` | `draft` | 作者修改并保存 | 医生 | 清除驳回状态，准备重新提交 |
| `rejected` | `reviewing` | 作者重新提交 | 医生 | 重置 ApprovalTask，从 N1 重新开始 |

### 注意事项
- 药企用户**不能**触发任何内容状态转换
- `reviewing` 状态映射到 6 桶 `WorkshopExtra.flowStatus` 以提供更细粒度的追踪（见 §1.1）
- `reviewed` 是一个临时状态 —— 内容应尽快发布或退回

### 1.1 工坊流程态（流水线内的子状态）

这些是**仅用于展示**的流水线阶段，存储在 `WorkshopExtra.flowStatus` 中。它们不是 `ContentItem.status` 的正式状态，而是提供更丰富的追踪：

```
需求已提交 → 医生分发中 → 医生制作中 → 三方审核中 → 内部审核中 → 已发布
```

| flowStatus | 映射到 ContentItem.status | 描述 |
|-----------|--------------------------|------|
| 需求已提交 | draft | 诉求已创建，尚未分配医生 |
| 医生分发中 | draft | 运营正在派单给医生 |
| 医生制作中 | draft | 医生正在撰写 |
| 三方审核中 | reviewing | 在药企（第三方）审核节点 |
| 内部审核中 | reviewing | 在 DX/PX 内部审核节点 |
| 已发布 | published | 已上线 |

## 2. 审批任务生命周期（`ApprovalTask`）

```
  ┌──────────────────────────────────────────────┐
  │                                              │
  ▼                                              │
┌──────────┐  通过   ┌──────────┐  通过         │
│  节点 0   │────────►│  节点 1   │───────► ...  │
│(DX医学审核)│         │(PX运营审核)│              │
└────┬─────┘         └────┬─────┘              │
     │ 驳回                │ 驳回               │
     ▼                     ▼                    │
┌──────────────────────────────────┐            │
│          已驳回                    │            │
│  (打回策略 = 医学编辑修改           │            │
│   → 返回节点 0 / DX)              │────────────┘
└──────────────────────────────────┘  (作者修改后
                                       重新提交)

  ... → ┌──────────┐  通过   ┌──────────┐
        │  节点 N   │────────►│   完成    │
        │ (药企审核)  │         │(全流程通过) │
        └────┬─────┘         └──────────┘
             │ 驳回
             ▼
        (同样的驳回流程)
```

### 转换表

| 动作 | 效果 | 详情 |
|------|------|------|
| **提交** | 创建任务 | `currentIdx = 0`，`rejected = false`，`startedAt = now`，首条历史记录 action='submit' |
| **通过**（节点 N） | 推进 | `currentIdx++`，`enteredAt = now`，历史记录 action='pass' |
| **通过**（末节点） | 完成 | `currentIdx >= flow.nodes.length` = "全流程通过"，内容状态 → `reviewed` |
| **驳回**（任意节点） | 返回起点 | `rejected = true`，`currentIdx = 0`，`enteredAt = now`，历史记录 action='reject'。根据"医学编辑修改"策略：始终返回节点 0（DX 医学审核） |
| **重新提交**（驳回后） | 重启流程 | `rejected = false`，`currentIdx = 0`，`enteredAt = now`，新增历史记录 action='submit' |

### SLA 计算

```typescript
const elapsedHours = (Date.now() - new Date(task.enteredAt).getTime()) / 3600000;
const slaHours = currentNode.timeoutHours; // 通常为 8
const isOverdue = elapsedHours > slaHours;
const remainingHours = Math.max(0, slaHours - elapsedHours);
```

超时时：行高亮为红色，触发超时动作（飞书提醒 = Lark 通知）。

## 3. 项目生命周期（`Project.status`）

```
┌─────────┐    ┌───────────┐    ┌──────────────┐    ┌───────────┐    ┌──────────┐
│  intake  │───►│ producing │───►│ distributing │───►│ completed │───►│ archived │
│  (受理中) │    │  (制作中)   │    │   (分发中)    │    │  (已完成)   │    │  (已归档)  │
└─────────┘    └───────────┘    └──────────────┘    └───────────┘    └──────────┘
```

### 转换表

| 从 | 到 | 触发 | 谁 |
|----|----|------|-----|
| *(新建)* | `intake` | 项目创建（管理员或自动从诉求创建） | ops-admin |
| `intake` | `producing` | 首条内容开始制作 | 系统（自动） |
| `producing` | `distributing` | 所有内容审批通过，开始分发 | 运营 |
| `distributing` | `completed` | 分发目标达成 | 运营 |
| `completed` | `archived` | 手动归档 | ops-admin |

### 注意事项
- 演示站在分发页面显示 5 个状态桶：受理中 4、制作中 6、分发中 2、已完成 2、已归档 0
- PRD 中使用 `producing`，但演示站在分发视图中标签为"制作中"，在管理/项目视图中标签为"进行中" —— **使用 `producing` 作为 key，不同上下文展示不同标签**

## 4. 诉求生命周期（`RequestTicket.status`）

```
┌─────────┐    ┌──────────────┐    ┌───────────┐    ┌──────────────┐    ┌───────────┐
│ pending  │───►│ in_progress  │───►│ in_review │───►│ distributing │───►│ completed │
│  (待受理) │    │   (进行中)    │    │  (审核中)  │    │   (分发中)    │    │  (已完成)   │
└────┬────┘    └──────────────┘    └─────┬─────┘    └──────────────┘    └───────────┘
     │                                    │
     │                                    │ (全部驳回)
     │                                    ▼
     │                              ┌──────────┐
     └─────────────────────────────►│ rejected │
              (直接驳回)              │  (已驳回)  │
                                    └──────────┘
```

### 转换表

| 从 | 到 | 触发 | 谁 |
|----|----|------|-----|
| *(新建)* | `pending` | 药企提交诉求 | 药企用户 |
| `pending` | `in_progress` | 运营受理并开始处理 | 运营 |
| `pending` | `rejected` | 运营驳回诉求 | 运营 |
| `in_progress` | `in_review` | 内容进入审批流 | 系统 |
| `in_review` | `distributing` | 所有内容审批通过 | 系统 |
| `in_review` | `in_progress` | 内容被驳回，回到制作 | 系统 |
| `distributing` | `completed` | 分发目标达成 | 运营 |

## 5. 租户生命周期（`Tenant.status`）

```
┌───────┐    ┌────────┐    ┌───────────┐
│ draft │───►│ active │◄──►│ suspended │
│ (草稿)  │    │ (已启用) │    │  (已停用)  │
└───────┘    └────────┘    └───────────┘
```

| 从 | 到 | 触发 | 守卫 |
|----|----|------|------|
| *(通过向导新建)* | `active` | 向导"创建租户并发出邀请" | — |
| `active` | `suspended` | 管理员切换开关 | 不可停用 `px_internal` 类型 |
| `suspended` | `active` | 管理员切换开关 | — |
| `draft` | `active` | 管理员激活 | — |

## 6. 账号生命周期（`Account.status`）

```
┌──────────┐    ┌────────┐    ┌────────┐
│ invited  │───►│ active │◄──►│ frozen │
│ (已邀请)  │    │ (已激活) │    │ (已冻结) │
└──────────┘    └────────┘    └────────┘
```

| 从 | 到 | 触发 | 守卫 |
|----|----|------|------|
| *(通过向导新建)* | `invited` | 管理员邀请账号 | — |
| `invited` | `active` | 用户接受邀请 / 首次登录 | — |
| `active` | `frozen` | 管理员切换开关 | `invited` 状态不可冻结 |
| `frozen` | `active` | 管理员切换开关 | — |

## 7. 子任务生命周期（`SubTask.status`）

```
┌──────────┐    ┌──────────┐    ┌───────────┐    ┌──────┐
│ assigned │───►│ drafting │───►│ reviewing │───►│ done │
│  (已分配)  │    │  (撰写中)  │    │  (审核中)   │    │ (完成) │
└──────────┘    └──────────┘    └───────────┘    └──────┘
```

| 从 | 到 | 触发 | 谁 |
|----|----|------|-----|
| *(新建)* | `assigned` | 运营派单给医生 | 运营 |
| `assigned` | `drafting` | 医生接受任务 | 医生（DX） |
| `drafting` | `reviewing` | 医生提交草稿 | 医生（DX） |
| `reviewing` | `done` | 医学编辑通过 | DX 编辑 |
| `reviewing` | `drafting` | 医学编辑驳回 | DX 编辑 |

## 8. 诉求子项状态（`RequestItem.status`）

```
┌──────┐    ┌──────────┐    ┌──────────┐    ┌───────────┐    ┌──────┐
│ todo │───►│ assigned │───►│ drafting │───►│ reviewing │───►│ done │
│(待处理)│    │  (已分配)  │    │  (撰写中)  │    │  (审核中)   │    │ (完成) │
└──────┘    └──────────┘    └──────────┘    └───────────┘    └──────┘
```

每个 RequestItem 追踪一条子项（主题 + 受众 + 形式）。状态跟随 SubTask 生命周期，因为每个子项映射到一个或多个 SubTask。
