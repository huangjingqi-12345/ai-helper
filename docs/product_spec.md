# Px Lite 产品规格草案

最后更新时间：2026-05-14  
状态：评审草案，等待 Leader / PM / CEO 确认。  
重要声明：本文档把当前 PM demo 作为展示基线，但不把 demo-only 行为自动认定为生产规则。

## 1. 产品定位

Px Lite 是面向中国医药场景的患者教育内容运营与聚合行为洞察平台。当前代码与 `docs/production_readiness.md` 的共同基线是：

- 以项目和内容为运营核心。
- 支持药企租户视角与 Px 运营视角。
- 支持内容工坊、行为洞察、分发策略、审批中心、平台管理、设置、财务演示等模块。
- 行为数据以聚合指标为边界，不保存患者 PII，不保存患者级行为事件。
- 生产环境应接入企业认证、租户隔离、审计日志、内容版本、审批动作追踪和导出保护。

## 2. 当前默认假设

| 假设 | 当前处理 |
|---|---|
| 当前仓库继续作为后续生产化基础 | 保留现有 full-stack 架构，不新建仓库 |
| PM demo 是展示基线 | 页面和交互可作为评审参考，但业务规则需确认 |
| 中文规格文档通过评审后作为开发依据 | 本文档包为下一阶段的输入 |
| 未确认功能不继续“边做边猜” | 统一放入 `docs/open_questions.md` |
| 财务模块尚未确认是否进入 v1 | 当前标记为 demo-only |

## 3. 用户角色草案

| 角色 | 当前系统对应 | 主要诉求 | 生产待确认 |
|---|---|---|---|
| Px 管理员 / 运营管理员 | `view_type=ops`、admin 类用户 | 查看全局总览、管理租户、账号、审批流、审计、数据导入导出 | 是否拥有所有租户数据明文权限；字段脱敏策略 |
| 内容运营 / 编辑 | editor 类用户 | 管理内容、查看内容状态、推进审批 | 内容创建/编辑/版本发布权限 |
| 分发运营 | 当前未完全独立建模 | 管理分发项目、选择医生/渠道、查看进度 | 是否需要独立角色与审批权限 |
| 药企用户 / 医学审核 | `view_type=pharma` | 查看本租户项目、内容、聚合数据，参与审批 | 可见页面、可见字段、导出权限、医学/市场角色区分 |
| 平台管理员 | admin + 平台管理页面 | 配置租户、账号、角色、审批流、系统设置 | 与 Px 管理员是否同一角色 |
| 财务运营 | 当前只有前端 demo | 合同、账单、发票、价值报告 | 是否进入 v1；如进入需完整财务模型 |
| 医生 / 外部创作者 | 当前有 `doctors` 表，前端未作为登录角色 | 内容制作、分发候选或专家池 | 是否需要医生端、登录、任务和结算流程 |

## 4. 产品模块规格草案

### 4.1 总览

**已实现/可演示行为**

- 展示项目数、已发布内容、触达/阅读/互动等 KPI。
- 展示项目列表与项目维度数据。
- 支持按租户视角进行不同范围的数据查询。

**当前实现规则**

- Px admin/ops 视角读取 `overview_stats` 快照。
- 药企/非 admin 视角按 `projects` 聚合部分指标。

**生产待确认**

- KPI 是否全部从明细表实时聚合。
- 是否保留 `overview_stats` 作为缓存/快照。
- 已发布内容展示为 `x/y` 的业务含义。
- 互动数是否包含 dislike。
- 项目状态与总览计数之间的关系。

### 4.2 内容工坊

**已实现/可演示行为**

- 内容列表和内容详情页。
- 内容归属项目、租户、疾病、品牌、标签、状态、workflow state、pipeline stage。
- 药企视图可以在内容工坊发起选题诉求：选择项目、填写诉求名、优先级、期望上线日、主题 × 形式篇数矩阵和备注。
- 提交诉求会写入 `content_requests`，并生成一条 `requirement_submitted` 草稿内容进入内容列表。
- 运营视图可以进入 `/distribute/request/:ticketId`，受理拆单、配置诉求级医生/患者分发策略，并提交主题 × 形式分发批次。
- 内容版本表 `content_versions` 已存在。
- 后端已有内容 CRUD 能力和药企诉求提交 API。

**当前 PM demo 行为**

- 前端更偏查看和状态展示，不代表最终编辑器、创建器、上传流程已经完成。

**生产待确认**

- `content_requests` 后续是否继续由 `request_distribution_batches` 派生医生制作任务，还是新增独立医生任务表。
- 运营是否允许绕过诉求直接创建内容。
- 医生制作稿、编辑修改稿、药企审核稿之间是否都要存版本。
- 内容发布后是否可修改；修改是否产生新版本与新审批。
- 内容素材 `content_assets` 的上传、存储、病毒扫描、权限规则。

### 4.3 行为洞察

**已实现/可演示行为**

- 汇总阅读、互动、趋势、Top 内容、疾病聚合等展示。
- 后端支持聚合行为数据导入。
- 后端支持导出任务和 k-anonymity 阈值检查。

**当前实现规则**

- 聚合导入时计算 `interaction_count = like_count + dislike_count + bookmark_count + share_count`。
- 药企视角使用租户范围内的 `behavior_daily_metrics` 聚合。
- Px demo 视角可以展示 seed 的趋势、Top 内容和疾病聚合。

**生产待确认**

- 行为数据来自哪里：埋点平台、第三方渠道、手动导入还是 API 集成。
- 指标粒度：天、项目、内容、疾病、品牌、渠道、地区。
- TopN 规则和“命中数量”的产品含义。
- 是否允许药企查看具体内容维度 Top 数据。
- 导出是否需要审批流。

### 4.4 分发策略

**已实现/可演示行为**

- 分发项目列表和详情页。
- 分发项目有优先级、状态、品牌、疾病、负责人、预期日期、总内容数、节奏、患者上限、话题、格式、审批流、进度、当前节点。
- 医生、医生专长、医生标签、候选匹配、分发记录等表已存在。

**demo-only 行为**

- 分发详情页中的部分需求 `liveRequests` 为前端硬编码。
- 分发详情页展示 6 节点演示流，不一定等于当前审批任务真实流。

**生产待确认**

- `projects` 与 `distribution_projects` 是同一项目的两种视图，还是两个业务实体。
- 分发进度 `progress` 和当前节点 `current_node` 是人工维护、流程计算，还是从任务完成率派生。
- 医生匹配规则：按疾病、地区、职称、标签、历史表现还是手工选择。
- 分发记录如何与内容阅读/互动回流关联。

### 4.5 审批中心

**已实现/可演示行为**

- 审批任务列表、状态筛选、单条通过、单条驳回。
- 审批流、节点、任务、动作日志均有数据库表。
- 当前 seed 中有 3 节点审批流：编辑审核 → Px 审核 → 药企审核。
- 单条审批会更新 `approval_tasks`、`approval_items`、`content`、最新 `content_versions`，并写入 `approval_task_actions`。

**demo-only 行为**

- 前端批量通过/驳回只显示演示 toast，不调用批量 API。
- 药企新发起的内容诉求已进入 `content_requests`；审批列表中既有 demo 需求分组仍通过前端 `requirementByContent` 硬编码。

**生产待确认**

- 审批流是否固定为 3 节点，还是允许租户配置。
- 驳回后返回提交人、上一节点、首节点还是终止。
- `approved` 表示当前节点通过还是全流程通过。
- `cancelled` 的业务含义。
- 批量审批是否进入 v1。

### 4.6 平台管理

**已实现/可演示行为**

- 租户、账号、项目、审批流配置页面。
- 租户范围 `tenant_scopes` 包含疾病/品牌/地区、灰度比例、k-anonymity、导出权限等字段。
- 用户、角色、权限、角色权限表已存在。
- 审计日志写入和读取已存在。

**生产待确认**

- 药企租户是否只能看自身数据；是否允许集团租户跨品牌查看。
- 权限矩阵中 `none/masked/aggregate/plaintext` 的字段级含义。
- SSO/MFA/Break-glass 管理流程。
- 审批流配置是否允许药企管理员修改。

### 4.7 设置

**已实现/可演示行为**

- 设置页展示团队成员和审计日志。
- 审计日志来自后端。

**demo-only 行为**

- 团队成员列表在前端本地硬编码和修改。

**生产待确认**

- 设置页团队成员是否直接等于 `users` 表。
- 是否允许在设置页管理成员，还是统一放在账号管理。
- 设置变更是否全部进入审计日志。

### 4.8 财务

**已实现/可演示行为**

- 财务首页、合同、账单、开票页面可展示。

**demo-only 行为**

- 财务数据全部为 `FinancePages.tsx` 的前端常量。
- 当前没有财务数据库表和财务 API。

**生产待确认**

- 财务是否进入 v1 production。
- 若进入，需要定义合同、报价、账单、对账、发票、回款、价值报告、审批和权限。
- 金额、税率、币种、发票状态、逾期提醒、收入确认口径。

## 5. 当前明确不作为已确认生产能力的内容

以下内容当前不能作为生产已完成承诺：

- 财务后端与财务数据库。
- 设置页团队成员真实管理。
- 审批批量通过/驳回真实执行。
- 分发详情页 `liveRequests` 和 6 节点流的最终规则。
- 患者级行为事件、患者 PII、自动内容医学判断。
- 真实客户 SSO 接入和权限矩阵验收。
- 完整医生端/外部创作者端。

## 6. 规格状态标记

后续评审建议对每条需求标记为：

| 标记 | 含义 |
|---|---|
| `CONFIRMED` | PM/CEO 已确认，可进入生产开发 |
| `DEMO-ONLY` | 只用于演示，不进入当前生产范围 |
| `ASSUMPTION` | 当前为了推进文档或 demo 做出的假设 |
| `OPEN` | 必须等待决策，不应直接开发 |
| `OUT-OF-SCOPE` | 明确不属于 v1 范围 |

## 7. 下一阶段建议

1. 先评审 `docs/spec_review_packet.md` 和 `docs/open_questions.md`。
2. 由 PM/CEO 确认 v1 范围、核心实体关系、KPI 与审批/分发/财务规则。
3. 把确认结果回写到本文档，并把开放问题关闭或转为明确假设。
4. 再创建生产化开发计划，按规格驱动实现。
